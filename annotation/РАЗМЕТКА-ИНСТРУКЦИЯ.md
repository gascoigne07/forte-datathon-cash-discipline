# Разметка типов нарушений — инструкция

Нужно посмотреть 21 видео и написать, **что именно** в каждом нарушено. Ничего
устанавливать не надо: только плеер, текстовый редактор и файл `labels.csv`.

## Зачем это нужно

В таблице от организаторов (`open_labels.xlsx`) указана только **секунда** нарушения —
какое именно нарушение, там не написано. Наш сервис уже выдаёт тип нарушения, но
сверить его не с чем. Из-за этого один из критериев оценки (корректность
классификации, **15 баллов из 100**) сейчас вообще не проверяется.

Вторая, не менее важная причина: **10 роликов из 21 сервис не находит вовсе.** Что в
них нарушено — мы не знаем. Пока кто-то не посмотрит глазами, под эти случаи
невозможно написать правило.

## Что понадобится

- Папка с видео: `open/videos/` (21 файл `.mov`, по 12–73 секунды).
- QuickTime (macOS) или VLC. Нужна покадровая перемотка:
  - **QuickTime** — стрелки `←` / `→` листают по кадру;
  - **VLC** — клавиша `E` листает по кадру, `пробел` — пауза.
- Файл `labels.csv` из этого же архива — в него писать.

## Порядок работы по одному ролику

1. Открыть ролик. В таблице ниже найти его **секунду**.
2. Перемотать на `секунда − 3` и проиграть **покадрово** до `секунда + 3`.
3. Понять, что происходит, и заполнить в `labels.csv` поля `type`, `what`, `cue`, `conf`.
   Строки `video` и `sec` уже проставлены — их менять не нужно.
4. Если на указанной секунде ничего особенного не видно — **посмотреть весь ролик
   целиком**, и если всё равно непонятно, поставить `type=unclear`, а в `what`
   описать, что вообще в ролике происходит.

Один ролик — примерно 2–3 минуты. Всего около часа.

## Поля файла

Разделитель — **точка с запятой** `;`. Внутри полей запятые можно, точку с запятой — нет.

| поле | что писать |
|---|---|
| `video` | уже заполнено, не менять |
| `sec` | уже заполнено, не менять |
| `type` | код из списка ниже |
| `what` | что происходит, своими словами, 5–15 слов |
| `cue` | **что именно на экране это доказывает** — предмет, место, действие |
| `conf` | `high` / `med` / `low` — насколько уверен |

## Коды типов

| код | что значит |
|---|---|
| `manual_count` | пересчёт наличных руками, счётная машина не используется |
| `cash_unattended` | наличные лежат на столе, кассир их не контролирует |
| `cash_handover` | деньги переданы из рук в руки / положены на стол мимо лотка |
| `left_workplace` | кассир ушёл с рабочего места, не убрав ценности |
| `cabin_open` | дверь кассовой кабины открыта / кабина не заперта |
| `safe_open` | сейф или шкаф оставлен открытым |
| `outsider` | посторонний в кассовом помещении во время операции с наличными |
| `food_drink` | стакан, кружка, банка, бутылка, еда на рабочем месте |
| `personal_bag` | личная сумка, рюкзак, пакет на рабочем месте |
| `sealed_bag` | инкассаторская сумка вне сейфа / передана без оформления |
| `phone_use` | кассир пользуется телефоном на рабочем месте |
| `other` | другое — обязательно описать словами в `what` |
| `unclear` | не видно, что именно нарушено |

## Три правила, которые важнее скорости

1. **Не угадывать.** `unclear` — нормальный и полезный ответ. Выдуманный тип хуже
   отсутствующего: по нему будет построено правило, которое даст ложные срабатывания
   на проверке у жюри. Лучше 8 честных строк и 13 `unclear`, чем 21 придуманная.

2. **`cue` писать физически.** Не «нарушение кассовой дисциплины», а
   «зелёная сумка лежит на столешнице, кассир стоит у стеклянной стены в 2 м от стола».
   Это поле — главное: из него выводится признак, по которому будет работать программа.

3. **Несколько событий — несколько строк.** Если в ролике два нарушения, добавить
   вторую строку с тем же `video` и своей секундой. Так уже известно про `Х-4` — он
   размечен дважды, на 57 и 68 секунде, обе строки в файле уже есть.

## Если останется время

По 5 чистых роликов — `Х-3`, `Х-10`, `Х-16`, `Х-21`, `Х-23` — записать в
`clean_notes.md` одной строкой: что кассир делает и **почему это НЕ нарушение**.
Это нужно, чтобы программа не ловила норму: в чистых роликах кассир тоже встаёт и
отходит, посторонние тоже заходят, наличные тоже лежат на столе.
