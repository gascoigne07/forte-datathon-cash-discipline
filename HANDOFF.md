## 1. Что это за задача

Локальный AI-сервис: жюри загружает видео кассира → сервис возвращает вердикт
`violation` / `no_violation`, а для каждого события — тип нарушения, таймкод,
описание, 1–3 кадра-доказательства (base64 JPEG) и ссылку на пункт НПА РК.

Жёсткие требования ТЗ:
- **Полная локальность**: никаких облачных AI-API, включая передачу кадров и их
  описаний наружу. За облако по API — дисквалификация (п.35).
- **5 минут на видео**, и жюри меряет лимит **от отправки**, а не от старта обработки.
- Только open source с **коммерческой лицензией** (п.24) + ForteBank получает право
  на коммерческое использование решения (п.34) → AGPL (Ultralytics YOLO) нельзя.
- Запрещены звук (п.28) и распознавание лиц (п.29).
- Нормативка — **только акты РК**, без выдуманных ссылок.

Порядок оценки, который определяет приоритеты: жюри сперва **автоматически
прогоняет API на 5+ тестовых видео**, и только потом приглашает на питч. Поэтому
критерии 1–3 (обнаружение 25 баллов, локализация 15, классификация 15) решают всё.

## 3. Архитектура

Каскад «дешёвое → дорогое», чтобы уложиться в 5 минут:

1. `perception.sample` — декодирование OpenCV на 2 fps.
2. `perception.detect` — RT-DETR v2 (Apache-2.0), люди и предметы.
3. `objects.resolve_desk_zone` — зона столешницы, 4 уровня: `wood` (тон дерева на
   медианном фоне) → `anchors` (статичная техника) → `roi` (объединение детекций) →
   `fallback` (константа). Способ возвращается наружу полем `zone_source`.
4. `objects.detect_objects` — треки предметов, появившихся по ходу записи
   (вычитание фона, люди вырезаются по боксам).
5. `perception.keyframes` — отбор ключевых кадров + обязательные моменты появления
   предметов.
6. `caption.caption` — **Florence-2-large (MIT)**, 2.7 с/кадр. Выбрана и по
   скорости, и по чистоте лицензии.
7. `caption.facts_from_caption` — извлечение фактов по ключевым словам с **учётом
   отрицания** и разбором предлогов («on the desk» против «holding»).
8. `rules.detect_events` — детерминированные правила → события.

Файлы сервиса (1681 строка всего):
`main.py` 134 · `pipeline.py` 309 · `rules.py` 290 · `objects.py` 274 ·
`perception.py` 251 · `caption.py` 195 · `jobs.py` 100 · `novelty.py` 72 ·
`schemas.py` 56

## 4. API — контракт, который нельзя ломать

```
POST /api/v1/analyze     file=<.mov>, заголовок X-API-Key  ->  {"job_id","status"}
GET  /api/v1/jobs/{id}   X-API-Key  ->  статус + результат
GET  /api/v1/health      ->  {"status","models":{"caption","detector"}}
GET  /                   ->  интерфейс
GET  /api/docs           ->  OpenAPI
```

Поля ТЗ: `verdict`, `violations[].type`, `.timecode_sec`, `.description`,
`.evidence_frames[].image_base64`, `.timestamp_sec`.

Поля сверх ТЗ (жюри может игнорировать): `confidence`, `window_sec`, `rule`
(реквизиты акта, пункт, **редакция пункта**, дословная цитата, ссылка на adilet,
флаг `verified`), `low_coverage`, `frames_analyzed`, `frames_total_sampled`,
`zone_source`.

Коды: без ключа **401**, не видеофайл **400**, >200 МБ **413**, неизвестный job
**404**. Все проверены живым прогоном.

Переменные окружения: `API_KEY`, `PORT`, `HF_HUB_OFFLINE`, `KF_CAP` (45),
`KF_STEP_SEC` (1.5), `WORKERS` (1), `CAPTION_MODEL`, `ANALYZE_BUDGET_SEC` (260),
`JOB_DEADLINE_SEC` (285), `MAX_UPLOAD_MB` (200), `NOVELTY` (0).

## 5. Что сделано этой ночью (шаги 0–9)

**Шаг 1 — правила.** Правило «посторонние» было мёртвым: условие `cash_seen` не
срабатывает никогда. Заменено на «трое и более + предмет на столешнице», серия 3
кадра. Вердикт 68 % → **72 %**, полнота 43 % → **52 %**, ложных по-прежнему одно.

**Шаг 2 — канал новизны.** Эмбеддинги столешницы SigLIP + банк нормы по 19 чистым
роликам. Калибровка **строго leave-one-video-out**. Результат отрицательный: при
пороге с нулём ложных находит **0 из 21**; чтобы найти 5, нужно 5 ложных.
Код оставлен под `NOVELTY=1`, по умолчанию выключен.

**Шаг 3 — дедупликация событий + таймкод.** События одного типа больше не
схлопываются в одно (три зоны: ≤3 с склейка, ≤12 с лучшее, >12 с оба),
`MAX_EVENTS` 4 → 6. Попутно: харнесс вызывал `detect_events` **без треков**, а
сервис с треками — замер Δt относился к несуществующей конфигурации. После
починки вскрылось, что уточнение таймкода цеплялось к трекам с нулевой секунды
(это фон, а не появление предмета): ≤3 с было 45 %, стало **55 %**.

**Шаг 4 — описания.** Собираются из фактов кадра (`facts_at_t`), а не из одной
фиксированной фразы. Английский текст модели в ответ не попадает. Лимит 460
символов. Исправлено три дефекта вывода, включая противоречие «людей в кадре: 1;
людей нет» (два независимых канала расходятся, когда детектор видит человека через
стеклянную стену).

**Шаг 5 — зона столешницы.** Решение собрано в `resolve_desk_zone`, добавлен
промежуточный уровень `roi` и поле `zone_source`. `tools/smoke_new_angle.py`
проверяет разметку сцены на любом видео **без загрузки модели описания** (секунды,
а не минуты). На всех 32 искажённых вариантах в константу не скатился ни один.

**Шаг 6 — единая таблица метрик.** `tools/metrics_summary.py` — один источник цифр
для README/SUBMISSION/PITCH, блок между маркерами, режим `--check`. При написании
счётчика устойчивости нашлась ошибка: варианты `planted_*` — это вклейка в
**чистый** ролик, для них `violation` верен, а счётчик писал их в ложные.

**Шаг 7 — нормативка.** `tools/check_editions.py` сверяет каждый цитируемый пункт
со сноской о редакции и проставляет поле `edition`. Первая версия скрипта соврала
на всех 14 нормах (баг регулярки) — после фикса сделан двусторонний контроль
прямым grep. Редакция выведена в API, в интерфейс и в `kb/NORMATIVE.md`.

**Шаг 8 — `tools/type_accuracy.py`.** Точность типа события по ручной разметке.
Читает `.xlsx` и `.csv`, **по заголовку, а не по позиции**.

**Шаг 9 — приёмка как у жюри.** Два дефекта, найденные только живым прогоном:

  сессий, поэтому не проявлялось. Переведено на `secrets.token_urlsafe`.
- `zone_source` не доезжал до ответа: добавил в конвейер и схему, а копирование в
  `job_status` не дописал. Исправлено перебором `JobResult.model_fields`.
- Полнота падала под нагрузкой: при пяти видео `Х-40` получал 13 кадров и терял
