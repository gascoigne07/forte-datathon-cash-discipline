## 1. Адреса и доступ

| Что | Значение |
|---|---|
| Веб-интерфейс | `<публичный URL>` |
| API | `<публичный URL>/api/v1` |
| Документация API | `<публичный URL>/api/docs` |
| Проверка живости | `<публичный URL>/api/v1/health` → `{"status":"ok"}` |
| API-ключ для жюри | `<ключ>` |

Ключ передаётся в заголовке `X-API-Key`. Запросы без верного ключа отклоняются с кодом 401.

```bash
# загрузка видео
curl -X POST <публичный URL>/api/v1/analyze \
     -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
# -> {"job_id":"3f2a9c1e","status":"processing"}

# получение результата (опрашивать раз в 2-5 секунд)
curl <публичный URL>/api/v1/jobs/3f2a9c1e -H "X-API-Key: <ключ>"
```

Обработка одного ролика занимает 130–225 секунд при лимите 300. Поля `verdict` и `violations`
появляются при `status: "done"`.

## 2. Инструкция по запуску и использованию

Полная инструкция — в [`README.md`](README.md), раздел 1. Кратко:

```bash
uv venv --python 3.12 .venv
VIRTUAL_ENV=.venv uv pip install torch torchvision transformers timm pillow numpy scipy \
    scikit-learn opencv-python-headless fastapi "uvicorn[standard]" python-multipart einops
.venv/bin/python -c "from huggingface_hub import snapshot_download as d; \
    d('florence-community/Florence-2-large'); d('PekingU/rtdetr_v2_r50vd')"
HF_HUB_OFFLINE=1 ./run.sh        # после загрузки весов интернет не нужен
```

Использование через интерфейс: ввести API-ключ → перетащить `.mov` → дождаться прогресса →
получить вердикт, таймлайн событий, карточки с кадрами-доказательствами и ссылкой на норматив.
Результат выгружается кнопкой «Скачать JSON».

## 3. Архитектура и используемые модели

Каскад «дешёвое → дорогое» (подробно — [`README.md`](README.md), раздел 3):

1. Декодирование и выборка 2 к/с (OpenCV).
2. Детекция людей и предметов — **RT-DETR v2**, Apache-2.0.
3. Геометрия сцены: медианный фон, зона столешницы по тону дерева, положение счётной машины.
4. Треки предметов, появившихся на столешнице (вычитание фона + трекинг блобов).
5. Описание ключевых кадров — **Florence-2-large**, MIT.
6. Разбор описаний в факты по ключевым словам и предлогам — детерминированный код.
7. Правила над фактами → события с типом, таймкодом и ссылкой на норматив.
8. Кадры-доказательства в JPEG/base64.

Обработка полностью локальная: при анализе видео сервис не делает сетевых запросов,
что проверяется запуском с `HF_HUB_OFFLINE=1`.

## 4. Нормативные источники и принцип сопоставления

Два акта, выгруженные и сверенные построчно:

1. **Постановление Правления Национального Банка РК от 29 ноября 2019 года № 231** —
   Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей
   в банках второго уровня… (рег. [V1900019680](https://adilet.zan.kz/rus/docs/V1900019680)).
2. **Постановление Правления Национального Банка РК от 24 февраля 2020 года № 14** —
   Правила организации охраны и устройства помещений банков второго уровня…
   (рег. [V2000020075](https://adilet.zan.kz/rus/docs/V2000020075)).

Принцип сопоставления: наблюдаемый на видео признак → тип события → конкретный пункт акта
с **дословной** цитатой. Соответствие хранится машинно в [`kb/rules.json`](kb/rules.json),
человекочитаемо — в [`kb/NORMATIVE.md`](kb/NORMATIVE.md).

**13 из 14 пунктов подтверждены дословно.** Один (еда и напитки на рабочем месте) помечен
`verified: false`: прямого запрета в актах нет, есть закрытый перечень разрешённого к вносу
в кассовый узел — это трактовка, и сервис показывает её с явной пометкой в интерфейсе и в JSON.
Выдуманных ссылок и пунктов в решении нет.

## 6. Ограничения и известные случаи ошибок

См. [`README.md`](README.md), раздел 7 — девять пунктов, каждый подкреплён замером.
Главное, что следует знать проверяющему:

- банкноты на разрешении 464×848 локальными моделями не распознаются (проверены четыре модели,
  сигнал инвертирован) — поведенческие нарушения с наличностью сервис пропускает;
- полнота на обучающей выборке — 27 % при нулевых ложных срабатываниях (0 из 20 чистых роликов);
- сервис выдаёт подсказку для проверки человеком, а не окончательное заключение.

## 7. Измеренное качество

| Метрика | Значение | Как воспроизвести |
|---|---|---|
| Верный вердикт | 62 % (26 из 42 файлов) | `tools/eval_caps.py` |
| Ложные срабатывания | 0 из 20 чистых роликов | там же |
| Полнота | 6 из 22 событий | там же |
| Ошибка таймкода | медиана 2.0 с, ≤3 с у 67 % | там же |
| Устойчивость зоны стола к искажениям ракурса | 12 из 12 вариантов в допуске (ширина ≤19 %, центр ≤9 %) | `tools/augment.py` + `tools/run_pipeline.py` |

Все отрицательные результаты и замеры отвергнутых подходов приведены в
[`01-FINDINGS.md`](01-FINDINGS.md) — это сделано намеренно, чтобы проверяющий видел,
на чём именно основаны ограничения решения.

## 8. Соблюдение ограничений ТЗ

| Требование | Как выполнено |
|---|---|
| Полная локальность (раздел 7, п.21, п.35) | все модели локальные, при обработке видео сетевых запросов нет, проверяется `HF_HUB_OFFLINE=1` |
| Переносимость во внутренний контур | веса в локальном кэше, конфигурация через переменные окружения, нет внешних CDN в интерфейсе |
| Open source с коммерческой лицензией (п.24, п.34) | Florence-2 — MIT, RT-DETR — Apache-2.0; Ultralytics YOLO (AGPL) намеренно исключён |
| Звук не используется (п.28) | аудиодорожка не читается |
| Лица не распознаются (п.29) | только детекция людей как объектов, без идентификации |
| Доступ по ключу (раздел 10) | `X-API-Key`, 401 без верного ключа |
| Формат `.mov`, до 200 МБ (п.25) | принимается, размер контролируется на загрузке |
| Два варианта вердикта (раздел 4) | `violation` / `no_violation` |
| Не утверждать то, для чего нужны невидимые данные (раздел 7) | формулировки описаний содержат только наблюдаемое; вывод помечен как подсказка |
